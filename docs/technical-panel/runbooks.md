# Регламенты обслуживания

## Поток ошибок вырос

Проверьте период, повторяемый номер проблемы, связанные события и затронутые версии. Отличайте подтверждённую серверную ошибку от отказа доступа. Запишите гипотезу отдельно от доказательства. Исправьте в репозитории, запустите проверки, опубликуйте через Actions, повторите исходный сценарий на безопасных данных. Закройте проблему с версией и результатом проверки. Не воспроизводите разрушительный сценарий на рабочей БД.

## Не входит пользователь

Проверьте блокировку, организацию, роль, обязательную смену пароля и события отказов. Сначала проверьте личность обратившегося. Выдавайте только одноразовое восстановление существующего аккаунта. Не возвращайте общий пароль 123456 и не выдавайте super_admin для обхода ошибки.

## Подозрительная инспекция / разные города

Откройте ИО, инспектора и географию. Проверьте источник города, полноту адреса, GPS-приблизительность и выезд сотрудника. Не используйте IP вместо адреса проживания. Приложите номер инспекции и основание проверки, не копии документов в комментарий. Сохраните относящиеся события для расследования. Блокировка не выполняется автоматически.

## Файл вызывает подозрение

Откройте метаданные и причину локальной проверки; совпадение SHA-256 доказывает только идентичность байтов. С правом files.original откройте оригинал; для PDF просмотрите все страницы. При необходимости поместите в технический карантин с основанием. Проверяйте соответствие полю и отсутствие экрана телефона вручную. Локальный алгоритм не гарантирует подлинность и не заменяет антивирус. Внешнее распознавание не подключено.

## Сервис недоступен

Сначала проверьте время наблюдения и состояние сборщика. Кнопка проверки выполняет безопасный повторный сбор без записи тестовых документов. Перезапуск — GitHub Actions → Deploy → restart после оценки последствий. Произвольные команды из браузера не выполняются. База не восстанавливается кнопкой в панели. Если backend полностью остановлен, панель покажет потерю связи; внешний независимый аварийный канал не настроен.

## Резервная копия устарела / проверка восстановления

Проверьте reestr-backup.timer, manifest, наличие дампа и архива storage, место на диске. Используйте ops/backup-reestr.sh, который выполняется перед штатным deploy. Проверяйте восстановление только в отдельной БД и отдельном каталоге: pg_restore с --exit-on-error, контрольные количества и выборочные контрольные суммы файлов. Не подключайте тест к production DATABASE_URL. Факт успешного отдельного теста не присваивается другим резервным копиям. Для production-восстановления нужны отдельное окно обслуживания, выбранная проверенная копия, ответственный и согласованный план отката.

## Хранение и архивы

События: аудит 365 дней, безопасность 90, ошибки 30. Ежедневный reestr-technical-retention.timer сначала пишет AES-256-GCM/gzip архив в /opt/reestr/archives, fsync файла/каталога, затем транзакционно удаляет только истёкшие записи без действующего hold. При ошибке архива записи не удаляются. Триггер запрещает обычные UPDATE/DELETE. Это защита приложения и БД, не внешнее WORM-хранилище; администратор PostgreSQL сохраняет техническую возможность вмешательства.

Ключ TECH_PANEL_ENCRYPTION_KEY защищает архивы. Храните его резервную копию отдельно в одобренном хранилище секретов; не выводите в Actions или чат. Текущий скрипт резервирования БД/storage не включает .env и не заменяет резервирование ключа. Папка архивов также требует отдельного резервирования в согласованное хранилище; внешнее хранилище в этом выпуске не подключено.

## Публикация и откат

Deploy technical panel выполняет backup и штатный deploy-services, устанавливает отдельный Next сервис reestr-tech под системным пользователем, HTTP ACME → TLS, сборщик и retention timers, включает закрытую выдачу media, создаёт владельца один раз и возвращает только зашифрованный пакет. APK не пересобирается.

Аддитивные миграции оставляют бизнес-данные на месте. Новые поля местоположения добавляются IF NOT EXISTS, существующие значения сохраняются. Для отключения панели: TECH_PANEL_ENABLED=false, остановить reestr-tech; таблицы журнала не удалять. Откат backend/admin штатным rollback не отменяет миграции и не должен возвращать публичный /storage/ alias. До отката проверьте совместимость ссылок media и снимите отдельную резервную копию. Конфигурация nginx до первого выпуска хранится закрыто в /opt/reestr/private.
