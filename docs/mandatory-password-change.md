# Обязательная смена временного пароля

Вход с временным паролем возвращает только `passwordChangeToken` со сроком
10 минут. Рабочие токены и сессия выдаются после успешной смены пароля.
Переход на рабочие экраны при незавершённой смене блокируется клиентом; сервер
независимо запрещает доступ до смены пароля.

Исправлена обработка старых сессий: отказ восстановления и локально истёкшая
сессия открывают экран повторного входа с пояснением. После проверки временного
пароля открывается обязательная форма. Неверный пароль при входе не вызывает
обновления другой сессии. Параллельные запросы используют одно обновление токена;
запоздавший ответ старой сессии не может очистить новый вход. Сетевые сбои и 5xx
не удаляют сохранённые учётные данные.

Единый пункт «Контрольный орган» поддерживает назначенные роли `nca` и
`government`. Сервер выбирает фактически назначенную роль из этих двух,
не добавляя пользователю привилегий. Клиент сохраняет разрешённый код роли.
Членство ИО и его роли проверяются отдельно по прежним правилам.

Диагностика `diagnose-passwords` в GitHub Actions читает только агрегаты:
количество временных паролей, обязательных смен, несовпадающих признаков и
активных сессий с требованием смены. Пароли, хеши, телефоны и токены не выводятся.
Диагностика и это исправление не сбрасывают личные пароли пользователей.

Проверки: `test/password_flow_test.dart` проводит ИО, НЦА и государственный орган
от отказа старой сессии через обязательную форму до успешной смены; проверяет
отклонение короткого пароля и запрет обхода формы. `test/session_password_test.dart`
проверяет параллельные запросы, сетевые сбои и гонку с новым входом.
`backend/src/auth/auth.service.spec.ts` проверяет ограниченные токены, назначенные
роли, отказ пользователям без полномочий и отзыв старых сессий.
