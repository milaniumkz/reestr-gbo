# Возврат инспекции в обратном порядке

Прямой маршрут: инспектор → контроль качества → руководитель → реестр.

Обратный маршрут:
- Руководитель возвращает запись из quality_approved в submitted: очередь контроля качества. Инспектор не получает право редактирования на этом этапе.
- Контроль качества забирает запись существующим механизмом назначения проверяющего. Он может исправить разрешённые данные и документы либо вернуть инспектору.
- Возврат из submitted сотрудником контроля качества переводит запись в rejected: инспектор может исправить её и снова отправить в контроль качества.
- После исправлений контроль качества повторно загружает актуальное свидетельство, подтверждает данные и отправляет руководителю. Для двух баллонов необходимы оба файла свидетельств.

Команда API rejected сохранена для совместимости со старыми клиентами. Сервер определяет целевой этап по текущему этапу и полномочиям отправителя. В журнале записываются исходный/фактический статусы, отправитель и returnTarget. Ранее созданные записи не переводятся массово.

При возврате руководителя снимаются текущие подтверждение качества, отметки актуальности загруженных свидетельств и назначение проверяющего, чтобы запись была доступна отделу качества. Старые файлы сохраняются. createdBy/submittedBy и время исходной отправки инспектором не заменяются руководителем. Записи/отчёты инспектора остаются защищены от редактирования контролем качества. Новых прав на утверждение или обход этапов нет.
