# Видеоидентификация инспекторов

Перенос из milaniumkz/intercity, ревизия 6e7e5b1005af825fce8405b4c26ea37628e25ba3. Сохранены серверный видеодвижок, модели и их проверки SHA256, случайные задания, русская озвучка Irina и предварительные подсказки положения лица. В браузере предварительное положение лица определяется локальной моделью. В нативном клиенте остаётся рамка и текстовые/голосовые инструкции без дополнительного клиентского детектора, чтобы сохранить поддержку существующего iOS 14; все обязательные проверки лица выполняет тот же серверный движок. Водительские документы, восстановление пароля InterCity и межпользовательский поиск лиц не включены.

## Правила доступа

Проверка нужна сотрудникам с ролью inspector (и старой inspection_org). Аккаунты с ролями руководителя admin или quality_control освобождены, в том числе смешанные аккаунты; глобальные административные/контрольные роли также освобождены. Проверяется членство в базе, а не роль, выбранная на экране входа, и не название платформы клиента.

При первом входе — отдельное согласие и первичная запись с двумя случайными заданиями за 14 секунд. Каждый новый сеанс требует новой 20-секундной записи с тремя заданиями и сравнения с эталоном. Обновление JWT в той же сессии сохраняет проверку. Без подтверждения сервер не допускает к рабочим API. Перепривязать эталон обычным входом нельзя.

Задание привязано к userId, sessionId, версии пароля и одноразовому секрету; действует пять минут. Принятие файла выполняется атомарно. Повтор файла и практически одинаковая последовательность кадров проверяются только внутри аккаунта. Сомнительный результат предлагает новую запись; несовпадение лица не даёт доступ. Сброс администратора отзывает сеансы и прежние задания. Сеанс, отозванный во время обработки, не получает доступ.

## Обработка и хранение

Видеодвижок работает локально, с сетью Docker internal, без исходящего доступа при обработке; порт публикуется только на 127.0.0.1:8091. Ограничения: 768 МБ, 1.5 CPU, 128 процессов, непривилегированный пользователь, read-only filesystem и временные файлы в tmpfs. Одновременно обрабатывается одна запись, при занятости предлагается повторить.

Эталон, контрольный снимок, первичное видео и неуспешные попытки зашифрованы AES-256-GCM с AAD=userId. Каталог /opt/reestr/storage/private/identity и ключ key.bin недоступны через публичные URL. Ключ включается в резервную копию хранилища; его утрата требует восстановления исходной копии. Первичные материалы хранятся до сброса или удаления аккаунта; неуспешные попытки — семь дней в рабочем хранилище. Успешные повторные видео не сохраняются. Резервные копии обслуживаются отдельно и могут содержать прежние зашифрованные записи.

Просмотр видео и сброс разрешены только super_admin и аудируются. Универсальные API пользователей не выдают шаблоны лица. Движок повышает устойчивость к фотографии, повторной записи и смене лица, но не аттестован и не гарантирует обнаружение любой виртуальной камеры/глубокой подделки. Точность на целевых устройствах отдельно не измерена.

## Развёртывание

1. CI и проверки настоящего MediaRecorder на синтетической камере; тесты реальных моделей без сети. Положительный браузерный тест с подменённым ответом API проверяет клиентский поток, а не распознавание настоящего человека.
2. identity-inventory: проверить диск/память. deploy-identity-engine: собрать закреплённый движок, проверить здоровье, выставить права приватного каталога и настроить 110-секундный тайм-аут видео-API на обоих HTTPS-хостах с резервной копией/откатом.
3. Обновить backend с миграцией, веб-клиент и Android APK. По умолчанию новое ограничение выключено. Существующие документы и инспекции не изменяются.
4. identity-pilot с UUID выбранного инспектора: функциональная проверка владельцем на своём устройстве. Другие аккаунты продолжают работать.
5. activate-inspector-identity: проверить движок и одинаковые версии backend/web, отозвать действующие сеансы только требующих проверки инспекторов, включить общую политику. Повторное включение не вызывает нового массового сброса.
6. Аварийное отключение: deactivate-inspector-identity. Оно не восстанавливает отозванные токены; сотрудники входят повторно по паролю. Автоматического обхода при недоступном движке нет.

Административный сброс находится в карточке пользователя: «Сбросить видеоидентификацию и сеансы», причина обязательна. Первичная запись закрепляет лицо того, кто первым успешно войдёт по правильному паролю и выполнит задания; это не государственная проверка удостоверения личности.
