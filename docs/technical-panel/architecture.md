# Техническая панель ЕРСИ ГБО: карта и границы

## Подтверждённые компоненты

| Компонент | Реализация | Источник мониторинга |
|---|---|---|
| Приложение | Flutter, `lib/`, Android/iOS/веб | Ответы API с серверным номером обращения; клиентские сообщения отдельно от доказанных операций |
| Основная админка | Next.js 16, `admin/`, порт 3001, `/admin` | Серверный аудит HTTP и бизнес-операций |
| Сервер | NestJS 12, `backend/src`, порт 3000 | Запросы, ошибки, время ответа, процесс Node, версия выпуска |
| База | PostgreSQL 16 / Prisma 6.12, локально образ PostGIS | Проверка SELECT 1, pg_stat_activity без текстов запросов |
| Файлы | `StorageService`, local или S3; production local `/opt/reestr/storage` | Проверка доступности без записи мусорных файлов, сведения StorageObject, хеши |
| Фотографии | sharp, local-screening-v2, 2 активных / 4 ожидающих | Реальный статус анализатора; ручная проверка PDF; внешнего ИИ нет |
| Очереди | BullMQ/Redis подключены в AppModule | Зарегистрированных обработчиков BullMQ в коде нет: не выдумывать задачи/успешную обработку |
| Планирование | systemd backup timer; пустой таймер InspectionsService | Публикация свидетельств ручная; таймер не выполняет автоматическое размещение |
| Уведомления | Таблица Notification, серверные API | Внутрисистемные записи; внешний подтверждённый канал доставки не подключён |
| Доступ | Телефон/пароль, обязательная смена 123456, JWT Session | Отдельная техническая авторизация не принимает обычные JWT и super_admin |
| Развёртывание | GitHub Actions, SSH/systemd/nginx, `ops/deploy-production.sh` | VERSION, история выпусков/резервных копий через ограниченный сборщик |

## Отдельная панель

`tech/`: тот же Next.js, отдельный процесс 3002 и префикс `/tech`, своя навигация и светлая/тёмная темы. API `/api/v1/technical`. Отдельные TechAccount/TechSession, роли owner/engineer/support/viewer, пароли без общего значения, обязательный TOTP. Обычные пользователи и администраторы реестра не становятся техническими сотрудниками автоматически.

Серверная проверка каждого разрешения, HttpOnly/SameSite cookie, проверка Origin и заголовка защиты мутаций. MFA-секрет шифруется отдельным ключом. Повторное подтверждение для управления доступом и восстановления. Веб-оболочка не выполняет SQL, команды оболочки и не редактирует секреты. Восстановление рабочей БД через браузер не реализуется: изолированная проверка и отдельная регламентная процедура.

## Сбор и согласованность

Сервер присваивает UUID запроса. Журнал HTTP включает окончательный результат, в том числе отказ guard. Исходные тела, query-string, cookies и заголовки авторизации не собираются. Аудит критических бизнес-изменений сохраняется с операцией в одной транзакции там, где она уже предусмотрена; изменения ролей/блокировок переводятся на транзакции. Ошибки группируются по стабильному отпечатку. Клиентские сообщения помечаются как сообщения клиента и не доказывают выполнение операции.

При отказе сбора видны число потерянных/отложенных событий и время последнего успеха. Ограниченная очередь журналов не может безгранично потреблять память. Для управления техническим доступом и защищёнными файлами запись аудита обязательна до выдачи данных/подтверждения изменения.

## Честные ограничения

Нет подключённого APM, антивируса, IP-географии, независимого хранилища неизменяемых журналов, внешних каналов тревог и подтверждённой доставки. Регистрация BullMQ не равняется наличию рабочих обработчиков. Файл резервной копии не доказывает восстановление. Недоступный сборщик метрик даёт «Нет данных», а не «Сервис исправен». Первоначально доступны только сохранённые исторические записи AuditLog; подробные события появятся после подключения сбора.

## Авторизация публикации

В последующем сообщении пользователь явно согласовал создание полноценной рабочей учётной записи владельца и публикацию панели. Повторно запрашивать это согласование не требуется. Не согласованы: новый внешний канал отправки, внешнее распознавание документов, разрушительные испытания и восстановление production-БД. Все проверки выполняются на синтетических данных в отдельной БД/хранилище.
